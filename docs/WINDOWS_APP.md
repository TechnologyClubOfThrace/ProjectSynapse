# Synapse v2 - Windows application

## Τρέχον milestone

Η `Synapse.App` είναι WinForms εφαρμογή για Windows 10/11 με εμφάνιση που
ακολουθεί τα συνήθη Windows controls. Δεν χρησιμοποιεί τη φωτογραφία της
παλαιότερης εφαρμογής.

Περιλαμβάνει:

- startup validation του manifest και των έξι WAV (5 layers + reference),
- αυτόματη ανακάλυψη πολλών συνθέσεων από τον τοπικό φάκελο compositions,
- επιλογή σύνθεσης πριν από την έναρξη μιας συνεδρίας,
- επιλογή ενεργού Windows output endpoint,
- audio preflight χωρίς αναπαραγωγή,
- ρητή προετοιμασία της mixer engine,
- USB/Serial σύνδεση ESP32-S3 στα 115200 baud,
- αυστηρό parsing του πρωτοκόλλου `LEVEL/VALUE/SMOOTH/SEQ/UPTIME`,
- ταξινόμηση των επτά ζωνών από την εφαρμογή βάσει της τιμής `SMOOTH`,
- ενιαία βαθμονόμηση συνεχόμενων επιπέδων `0–N` για τη συγκεκριμένη επιφάνεια,
- βιβλιοθήκη αποθηκευμένων calibration profiles με ελεγχόμενο άνοιγμα,
- επίμονος μετρητής εκτιμώμενων συμμετοχών με append-only ιστορικό,
- επτά ζώνες συμμετοχής με ασφαλή αντιστοίχιση σε πέντε audio layers,
- simulator συμμετοχής 0–7 για δοκιμές χωρίς ESP32,
- heartbeat timeout 2,5 seconds που επιβάλλει επίπεδο μηδέν και fade-out,
- προβολή φάσης, πραγματικού χρόνου επαφής και ενεργών layers,
- τελική ουρά από 180,000 έως 183,101 seconds,
- πλήρη οθόνη, reset, status bar και περιορισμένο runtime log,
- ανεξάρτητη σίγαση μουσικής με fade, χωρίς παύση καταγραφής ή LEDs,
- προαιρετική τεχνική καταγραφή αισθητήρα σε τοπική SQLite βάση,
- μετάβαση σε ασφαλή κατάσταση fault όταν χαθεί η συσκευή ήχου.

Η v2 παραμένει σκόπιμα σε αρχιτεκτονική **ενός αισθητήρα αφής**. Πιθανή
επέκταση σε πολλαπλούς αισθητήρες ανήκει στη v3 και δεν αλλάζει το σταθερό
serial/calibration baseline της παρούσας έκδοσης.

## Ασφαλής εκκίνηση για ανάπτυξη

```powershell
dotnet run --project .\src\Synapse.App\Synapse.App.csproj `
  --configuration Release --no-build -- `
  --compositions .\local-data\compositions `
  --calibrations .\local-data\calibrations `
  --runtime .\local-data\runtime
```

Η εκκίνηση δεν παίζει ήχο. Η αναπαραγωγή μπορεί να αρχίσει μόνο αφού ο
χειριστής πατήσει **Προετοιμασία ήχου** και είτε συνδέσει το ESP32 είτε αλλάξει
τον simulator από 0 σε 1–7.

Η αντιστοίχιση συμμετοχής προς μουσικά layers είναι:

| Συμμετοχή | Layers |
|---:|---:|
| 0 | 0 |
| 1 | 1 |
| 2 | 2 |
| 3 | 3 |
| 4–5 | 4 |
| 6–7 | 5 |

## State machine παρουσίασης

1. `Ready`: η engine περιμένει επαφή.
2. `Building`: τα layers 1–5 ενεργοποιούνται με frame-aligned fades.
3. `Paused`: μετά από 250 ms χωρίς επαφή ολοκληρώνεται fade-out και γίνεται
   πραγματικό WASAPI pause.
4. `Climax`: από τα 160 seconds πραγματικής επαφής ακούγονται και τα 5 layers.
5. `Ending`: στα 180 seconds αγνοείται η είσοδος και ακούγεται ολόκληρη η ουρά.
6. `Ready`: στα 183,101 seconds σταματά και μηδενίζεται η συνεδρία.

Μετά από 20 seconds αδράνειας πριν από την κορύφωση η συνεδρία μηδενίζεται.
Οι χρόνοι αλληλεπίδρασης και ουράς δεν είναι πλέον σταθερές του κώδικα·
διαβάζονται από το `manifest.json` της επιλεγμένης σύνθεσης.

## Βαθμονόμηση αφής από την εφαρμογή

Το firmware συνεχίζει να στέλνει `raw`, `smooth`, `SEQ`, `UPTIME` και το δικό
του `LEVEL`. Η εφαρμογή χρησιμοποιεί το `smooth` για την τελική απόφαση του
ήχου. Το `LEVEL` του firmware εμφανίζεται μόνο ως διαγνωστική πληροφορία και
δεν ενεργοποιεί μουσικά layers.

Η βαθμονόμηση γίνεται μόνο όταν η εφαρμογή είναι σε κατάσταση **Έτοιμο**, ο
ήχος έχει προετοιμαστεί και το ESP32 είναι συνδεδεμένο:

1. Πατήστε **Βαθμονόμηση**. Κατά τη διαδικασία ο ήχος παραμένει ασφαλώς
   απενεργοποιημένος.
2. Καταγράψτε ανεξάρτητα τις καταστάσεις **Χωρίς επαφή** και
   **Επαφή επιπέδου 1–7**. Κάθε μέτρηση περιλαμβάνει 2 seconds σταθεροποίησης
   που δεν αποθηκεύονται και μετά 12 seconds πραγματικής καταγραφής. Μπορεί να
   επαναληφθεί χωρίς να χαθούν οι υπόλοιπες.
   Το **Ακύρωση μέτρησης** σταματά μόνο την τρέχουσα καταγραφή και διατηρεί
   τυχόν προηγούμενη έγκυρη μέτρηση της ίδιας γραμμής. Το **Μηδενισμός**
   διαγράφει μόνο τη συγκεκριμένη γραμμή και επανυπολογίζει την εγκυρότητα.
3. Ελέγξτε τα `min`, `median` και `max` κάθε κατάστασης.
4. Απαιτούνται τουλάχιστον τα επίπεδα `0` και `1`. Επιτρέπεται partial profile
   `0–N`, αρκεί οι καταγραφές να είναι συνεχόμενες και να μην επικαλύπτονται.
   Τα επίπεδα `N+1–7` παραμένουν ανενεργά και δεν προκαλούν καμία ενέργεια.
5. Πατήστε **Αποθήκευση** μόνο όταν το ενιαίο profile εμφανίζεται ως έγκυρο.
   Η αποθήκευση ενημερώνει με ασφάλεια και το ενεργό profile.

Το πεδίο **Αποθηκευμένο profile** εμφανίζει τα έγκυρα ονομαστικά JSON profiles
του φακέλου βαθμονόμησης. Το **Άνοιγμα** φορτώνει το επιλεγμένο profile μόνο
στο παράθυρο επεξεργασίας. Δεν αλλάζει την ενεργή βαθμονόμηση μέχρι να
πατηθεί **Αποθήκευση**. Μη έγκυρα JSON αρχεία απομονώνονται και δεν εμποδίζουν
τη φόρτωση των υπόλοιπων profiles.

Το ενεργό profile δεν αντικαθίσταται κατά τις επιμέρους καταγραφές. Ακύρωση,
κλείσιμο ή αποτυχημένη επικύρωση αφήνουν το προηγούμενο profile αμετάβλητο.
Όταν ανοίγει η φόρμα, προφορτώνει τις ήδη αποθηκευμένες περιοχές και επιτρέπει
επέκταση με το αμέσως επόμενο επίπεδο χωρίς επανάληψη των προηγούμενων.
Μείωση του μέγιστου ενεργού επιπέδου απαιτεί δεύτερη ρητή επιβεβαίωση.

Πριν από κάθε αντικατάσταση του `active-calibration.json`, η προηγούμενη
έκδοση αντιγράφεται με timestamp στο `local-data/calibrations/history`. Έτσι μια
λανθασμένη αποθήκευση είναι ανακτήσιμη χωρίς να βασίζεται σε προσωρινά αρχεία.

Η πραγματική βαθμονόμηση των επιπέδων `2–7` απαιτεί αντίστοιχες ταυτόχρονες,
αντιπροσωπευτικές επαφές στην τελική κατασκευή. Μετρήσεις από ένα μόνο άτομο
ή απλή μαθηματική παρεμβολή δεν θεωρούνται τελική επικύρωση εγκατάστασης.

Η εφαρμογή απορρίπτει τη βαθμονόμηση όταν διαδοχικές περιοχές τιμών δεν έχουν
ασφαλή απόσταση. Τα τοπικά JSON profiles γράφονται στο
`local-data/calibrations`, δεν περιλαμβάνονται στο Git και το ενεργό profile
φορτώνεται στην επόμενη εκκίνηση. Η υστέρηση (`hysteresis`) αποτρέπει γρήγορες
εναλλαγές κοντά στα όρια.

## Σίγαση μουσικής χωρίς διακοπή καταγραφής

Το **Σίγαση μουσικής** εφαρμόζει ανεξάρτητο master fade στην έξοδο ήχου. Δεν
σταματά το session clock, δεν αλλάζει τα επίπεδα συμμετοχής και δεν επηρεάζει
τη δημιουργία Συνάψεων ή τη λειτουργία των LEDs του ESP32. Το
**Ενεργοποίηση μουσικής** επαναφέρει ομαλά την έξοδο στην τρέχουσα χρονική
θέση της σύνθεσης. Έτσι η μουσική παραμένει συγχρονισμένη με τη συνεδρία.

## Μετρητής εκτιμώμενης συμμετοχής

Η εφαρμογή μετρά ομάδες επαφής μόνο από το πραγματικό ESP32. Κάθε κύκλος
`0 → επαφή → 0` καταγράφεται μία φορά, με το μέγιστο επίπεδο που εμφανίστηκε
ως εκτιμώμενο πλήθος συμμετοχών. Η ομάδα οριστικοποιείται μόνο μετά από
3 seconds συνεχόμενης μη επαφής· συντομότερο άφημα και νέα επαφή συνεχίζουν
την ίδια ομάδα. Ο simulator δεν επηρεάζει τον μετρητή.

Στην κύρια οθόνη εμφανίζονται η τρέχουσα εκτίμηση, οι συνολικές συμμετοχές,
το πλήθος ομάδων και το μέγιστο ταυτόχρονο επίπεδο. Τα γεγονότα γράφονται στο
append-only `local-data/runtime/participation-events.jsonl` μαζί με χρόνο,
διάρκεια, ενεργό calibration profile και λόγο ολοκλήρωσης. Σε απώλεια
heartbeat η ενεργή ομάδα κλείνει με ένδειξη `input-loss`.

Το **Μηδενισμός μετρητή** ζητά επιβεβαίωση. Δεν διαγράφει το αρχείο· γράφει
γεγονός `reset`, ώστε να διατηρείται το ιστορικό και να μηδενίζονται μόνο τα
εμφανιζόμενα σύνολα της νέας περιόδου.

## Προαιρετική τεχνική καταγραφή αισθητήρα

Η περιοχή **Είσοδος ESP32** διαθέτει ανεξάρτητο διακόπτη τεχνικής καταγραφής.
Κατά την εκκίνηση είναι πάντα ανενεργός και ενεργοποιείται μόνο με ρητή
ενέργεια του χειριστή, αφού συνδεθεί το ESP32. Η κανονική καταγραφή Συνάψεων
στο JSONL λειτουργεί ανεξάρτητα και δεν επηρεάζεται από αυτόν τον διακόπτη.

Όσο η τεχνική καταγραφή είναι ενεργή, κάθε έγκυρο Serial packet αποθηκεύεται
στο `sensor-telemetry.sqlite` του runtime directory. Καταγράφονται:

- UTC χρόνος, `raw`, `smooth`, firmware level και app level,
- `SEQ` και `UPTIME`, όταν παρέχονται από το firmware,
- φάση `idle`, `stabilizing`, `calibration`, `active` ή `release-delay`,
- το `eventId` της σχετικής Σύναψης, όταν υπάρχει ενεργός κύκλος επαφής,
- το ενεργό calibration profile, η σύνθεση, η θύρα COM και η έκδοση εφαρμογής
  ως metadata της telemetry session.

Η εγγραφή γίνεται σε bounded background queue και σε μικρές SQLite
transactions με WAL, foreign keys και `synchronous=FULL`. Η διακοπή του
διακόπτη, η αποσύνδεση/απώλεια heartbeat και το κανονικό κλείσιμο της
εφαρμογής αδειάζουν πρώτα την ουρά και ολοκληρώνουν τη session. Σφάλμα της
βάσης απενεργοποιεί μόνο την τεχνική καταγραφή· ο ήχος, τα LEDs και το JSONL
των Συνάψεων συνεχίζουν.

Η βάση είναι αποκλειστικά τοπική, δεν αποστέλλεται αυτόματα και δεν περιέχει
ταυτότητα επισκέπτη. Περιέχει όμως ακριβείς χρονικές στιγμές αλληλεπίδρασης,
οπότε πρέπει να διατηρείται μόνο για όσο απαιτείται ο τεχνικός έλεγχος.

## Τι έχει επαληθευτεί

- Release build με μηδενικά warnings/errors.
- Κοινό mixer clock για 5 providers.
- Stereo frame-aligned gain ramps.
- Master safety ceiling.
- Validation του πραγματικού manifest και των WAV.
- Strict parser tests για έγκυρα, ελλιπή και εκτός ορίων Serial packets.
- Sequence tracking για duplicate, out-of-order packet και επανεκκίνηση ESP32.
- Unit tests για app-side calibration, monotonic thresholds και hysteresis.
- Unit tests για ενιαίο ή partial profile `0–N`, απενεργοποίηση των μη
  καταγεγραμμένων επιπέδων και απόρριψη επικαλυπτόμενων περιοχών σήματος.
- Πραγματικό SQLite test για start/stop, ασφαλές queue drain, συσχέτιση με
  `eventId` Σύναψης και κλείσιμο ενεργής telemetry session κατά το disposal.
- Πραγματικό Serial preflight με τρία διαδοχικά heartbeat packets από ESP32-S3.
- Preflight του τρέχοντος Windows audio endpoint χωρίς playback.
- Φυσικό unplug test: άμεσο fade-out και μετάβαση σε ασφαλές pause.
- PNG render σε 1366x768: ο telemetry διακόπτης, το runtime log και τα 5
  μουσικά επίπεδα είναι ορατά χωρίς επικάλυψη.

## Τι δεν πρέπει ακόμη να θεωρηθεί ολοκληρωμένο

- Δεν έχει γίνει ακουστική δοκιμή με την τελική κάρτα ήχου και τα τελικά ηχεία.
- Δεν έχει γίνει τετράωρο soak test ούτε δοκιμή με την τελική μεταλλική
  κατασκευή.
- Έγινε compile, πλήρες rollback backup και upload του νέου firmware στο
  ESP32-S3. Έχει επαληθευτεί heartbeat-loss με φυσική αποσύνδεση.
- Τα thresholds του ενεργού app profile παραμένουν προσωρινά μέχρι να γίνει
  βαθμονόμηση στην τελική μεταλλική κατασκευή. Τα thresholds και το `LEVEL`
  του firmware είναι μόνο διαγνωστικά για τη v2.
- Δεν έχει παραχθεί και ελεγχθεί self-contained `win-x64` πακέτο σε καθαρό
  Windows 10/11 υπολογιστή.

Αυτά είναι απαραίτητα release gates πριν από δημόσια παρουσίαση.
